## 1. commander

`commander` 15.0.0 (2026-05-29, MIT, `engines.node >= 22.12`); Node here is 22.16. `exitOverride()`
turns usage errors into a `CommanderError` (exit code 1) instead of `process.exit`, so `runCli` can
run in-process in the tests; `configureOutput` sends commander's own messages to the test's streams.

## 2. Putting `cuttle` on PATH

`pnpm link --global` needs pnpm's global bin dir on PATH: `pnpm bin -g` says
`The configured global bin directory "C:\Users\ender\AppData\Local\pnpm\bin" is not in PATH. Run
"pnpm setup"`, which edits the user's environment. Not done. `%APPDATA%\npm`
(`C:\Users\ender\AppData\Roaming\npm`, npm's global prefix) is on PATH on every Windows Node
install, as are `~/.local/bin` and `~/bin` here. So `pnpm cli:install` writes small shims
(`cuttle.cmd`, `cuttle.ps1`, `cuttle` for Git Bash) there that run the bundled CLI with node, each
with a marker comment; shims without the marker (another tool's `cuttle`) are never overwritten;
`pnpm cli:uninstall` removes ours. `CUTTLE_BIN_DIR` picks another folder (the tests use a temp one).

## 3. Electron from Node

`require('electron')` in Node returns the binary's path
(`…\node_modules\.pnpm\electron@44.7.2\node_modules\electron\dist\electron.exe`), so the Node CLI
spawns Electron for the commands that need Chromium (render, preview, capture-page). The request goes
in as one base64 JSON argument (the last one: Chromium switches come before the script).

Found when the plan was replayed on a fresh clone: Electron 44 downloads its binary on the first
`require('electron')` (pnpm 11 runs no install scripts, so a fresh install has none) and prints
`Downloading Electron binary...` with `console.log`, plus the installer's own output, on stdout. The
first `cuttle --json preview` then printed that before its JSON and the check failed with
`Unexpected token 'D', "Downloadin"... is not valid JSON`. The CLI now reads the path itself
(`node_modules/electron/path.txt` names the executable inside `dist/`) and, when the binary is
missing, runs `install.js` with stdout and stderr on its own stderr (checked by moving `dist/` away:
stdout stayed one JSON document, the binary came back from Electron's download cache).

## 4. capture-page, first try

- A hidden `BrowserWindow` (`show: false`) does not paint: `Page.captureScreenshot` with
  `captureBeyondViewport: true` hung. With `paintWhenInitiallyHidden: true`,
  `backgroundThrottling: false`, `Emulation.setDeviceMetricsOverride({ width: 1920, height:
  <scrollHeight>, deviceScaleFactor: 1 })` and `Page.captureScreenshot({ fromSurface: true })` the
  treg landing page came out 1920×2036 in 4.4 s (Leaflet map tiles from the network included).
- `webContents.capturePage()` returns device pixels: at 125 % a 1920×1080 window gave 2402×1334.
  Use the device-metrics override with `deviceScaleFactor: 1` for exact sizes.
- Section 8 replaced this with an offscreen window.

## 6. A real Ctrl+C on Windows

Test rig: Python starts `node cuttle.mjs …` in a new hidden console (`CREATE_NEW_CONSOLE`), a koffi
helper attaches to that console (`FreeConsole`, `AttachConsole(pid)`,
`SetConsoleCtrlHandler(NULL, TRUE)`) and sends `GenerateConsoleCtrlEvent(CTRL_C_EVENT, 0)`.
- Git Bash passes an inherited "ignore Ctrl+C" to every child (a plain `process.on('SIGINT')`
  script got nothing); the CLI under test re-enables it with a preload
  (`SetConsoleCtrlHandler(NULL, FALSE)`), as in a user's own console.
- `cuttle record --backend test --webcam --mic`: Ctrl+C after 4 s → "stopping (stop)", exit 0
  after 1.07 s, all three tracks complete (4.17 s). The ffmpeg children (spawned with
  `windowsHide`) have no console and do not get the Ctrl+C themselves; the recorder stops them
  with `q`.
- `cuttle render`: Node got the Ctrl+C, **Electron did not** (it runs without a console), and the
  render ran to the end. **Electron's main process reads no stdin on Windows** (`process.stdin`
  ends at once), so a "cancel" line on stdin does nothing either. **Node's IPC channel works**
  (`stdio: [..., 'ipc']`, `process.on('message')` in Electron's main process): with the cancel and
  the answer over IPC, Ctrl+C after 3 s gave exit 130 after 1.08 s, "the export was cancelled", no
  output file, no work folder. (M3's open point "a real Ctrl+C during the audio pass" is the same
  path: the cancel now reaches Electron, which aborts ffmpeg.)

## 7. The CLI end to end (test backend)

`init` → `record --backend test --webcam --mic --max 5` (5.2 s take, project points at it) →
`suggest` → `preview` (12 stills + sheet in 4.2 s; the sheet shows the framed testsrc with labels) →
`capture-page <treg index.html> --scroll --add` (1920×2036, still scene appended) →
`render --format 9:16` (276 frames, 9.2 s, 3.8 s wall time). Bundle: `cuttle.mjs` 193 KB,
`electron.mjs` small, shared chunks next to them, `export-page/` copied by a second Vite build (the
CLI build empties `dist/`, so it runs first).

## 8. capture-page needs offscreen rendering

A still page (a plain gradient) in a hidden on-screen window never produced the frame that
`Page.captureScreenshot` waits for: the capture hung (now a 20 s timeout). `webContents.invalidate()`
did not help. The treg page only worked because Leaflet keeps repainting. An offscreen window
(`webPreferences.offscreen: true`) paints into a buffer: with the device-metrics override at scale 1
and a clip, both pages came out at their exact sizes (1920×3000, 1920×2039) in ~1.1 s, fonts and map
tiles included. (`capturePage()` of the offscreen window alone was 1–2 px off at 125 %.)

  2026-10-16T11:29:53.338+01:00. `cuttle recover takes/1` wrote events.jsonl and markers.json (empty)

  original demo sped it up 12×. Two rule changes: Claude's turn (first prompt or tool marker to the
  answer) is never cut, and a speed-up shows about 1/12 of its stretch (3–10 s of video, nice speeds
  only). Result: 1 s at 1×, 145.1 s at 12× (12.1 s), the answer at 1×: like the original.
- No zoom: the answer scrolled the whole terminal, so the changed area covered most of the screen
  (suggest says so). The JSON edits: a zoom on the answer block, `capture-page index.html
  --scroll --add --duration 6 --wait 2500`, an end card "Claude Code + treg" / "treg.to", the frame

- `cuttle render`: 713 frames, 23.77 s, 1920×1080 H.264 + AAC, 12.8 s wall time. The sheet shows the

## 10. Errors while Electron loads

The roadmap asked for the `uncaughtException` handler in a tiny bootstrap entry: a failure while
the bundle's static imports load would otherwise show Electron's modal dialog. `dist/electron.mjs`
is now `bootstrap.ts` (the handler, then `import('./main')`). With the main chunk renamed away, the
CLI printed `Cannot find module …main-….mjs` as its error and exited, no dialog. Electron's own error
codes (`ERR_MODULE_NOT_FOUND`) are not the CLI's: unknown codes from Electron become `render` (exit 3).
