# Phase 4 spike: speech, the content area, OCR

Date: 2026-10-17. Machine: Windows 11 Pro 26200, AMD Radeon integrated GPU, primary display
2560×1440 at 125 %, ffmpeg 9.0 (gyan.dev full build, with the `whisper` filter), Windows
PowerShell 5.1.

The spike scripts live in the planning session's scratchpad (`p4spike/`). The design spec that
uses these results is `docs/superpowers/specs/2026-10-17-cuttle-phase4-design.md`.

Nothing was shown on the user's screen. The only frames read were from the user's own take of a
public landing page, cropped to the page first so that no tab title reached the OCR. The secrets
on the test page are all fake: a test IBAN, a test card number and invented keys.

## 1. Models

`download-models.mjs` fetched each file from `huggingface.co/ggerganov/whisper.cpp` and checked
the SHA-256 in its Git LFS pointer. They were saved to `%LOCALAPPDATA%\Cuttle\models`, where the
app will look for them.

| Model | Size | Download |
|---|---|---|
| `ggml-base.bin` | 148.0 MB | 12 s |
| `ggml-small.bin` | 487.6 MB | 38 s |
| `ggml-large-v3-turbo-q5_0.bin` | 574.0 MB | 48 s |

## 2. Speech fixtures

`tts.ps1` uses Windows PowerShell 5.1 and `System.Speech`, with the voices Microsoft Hedda (de-DE)
and Microsoft Zira (en-US). It writes a 16 kHz mono WAV and the true start of every word from
`SpeakProgress`. SSML breaks make pauses.

The fixtures:
- `de`: 21.5 s, with "Äh", "Ähm", "Nochmal" and a repeated sentence;
- `en`: 18.7 s, with "Uh", "Um", "Again" and a repeat;
- `long`: 120.8 s, the two three times over.

A PowerShell 5.1 script with non-ASCII text must be saved with a UTF-8 BOM. Without one it is
read as ANSI, and the second byte of "Ä" (0x84) becomes a quotation mark.

## 3. Whisper through ffmpeg

`whisper-bench.mjs` runs `-af whisper=model=…:language=auto:format=json:destination=…:max_len=1:queue=…:use_gpu=…`.

**Findings about the filter itself:**

- **`queue`** is how much audio each transcription sees. The default of 3 s breaks words at the
  chunk edges ("Karte" became "K…" "How to.", "Nochmal" became "No." "Mal."). 30 s, whisper's
  own window, fixes that.
- **`use_gpu=1` works** here: about twice the speed of `use_gpu=0` with the same text.
- **The JSON output is not valid JSON.** A quotation mark in the speech is written unescaped
  (`"text":""Die"`). Each line has to be read with a pattern:
  `^\{"start":(\d+),"end":(\d+),"text":"(.*)"\}$`.
- **Escaping.** A Windows path in a filter option needs the drive colon escaped for both parsing
  levels: `C\\:/Users/…`. Git Bash also rewrites such arguments, so ffmpeg is started from Node
  with `spawn`.
- `max_len=1` gives one word per line, with start and end in milliseconds.

**Quality and speed:** queue 30 s, GPU on. WER is the word error rate against the TTS text.

| Model | WER de | WER en | Real-time factor (120.8 s fixture) |
|---|---|---|---|
| base | 0.316 | 0.027 | 20.1× |
| small | 0.132 | 0.054 | 4.9× |
| large-v3-turbo-q5_0 | 0.105 | 0.027 | 2.6× |

`base` is not good enough for German. `small` is the default ("Good"): a one-minute take
transcribes in about 12 s. `large-v3-turbo-q5_0` is "Best"; `base` is "Fast", with a note that it
suits English.

**Word times.** With a 30 s window, the word starts drift within a segment: a median error of
445 to 575 ms, and 1.1 to 1.3 s for the slowest tenth. The pauses land in the wrong places.

- Transcribing each speech chunk alone (`whisper-chunks.mjs`) gives a median of 165 to 250 ms. But
  it reloads the model per chunk: `turbo` falls to 0.33× real time, and the context shrinks
  (`small` de WER 0.29).
- **Alignment** (`align.mjs`) keeps one run and refines the times by the audio:
  - `silencedetect` (−35 dB, 0.25 s) finds the speech stretches;
  - dynamic programming gives each stretch, in order, the run of words whose letters fit its length
    at the take's speaking rate, near where whisper put them;
  - inside a stretch, the words share its length by their letters;
  - a stretch shorter than 0.8 s may take no word, cheaply.

Start errors against the TTS truth:

| Run | Before (median / p90) | After (median / p90 / max) |
|---|---|---|
| small de | 245 / 675 ms | 35 / 100 / 213 ms |
| small en | 445 / 1290 ms | 76 / 214 / 671 ms |
| turbo de | 530 / 1235 ms | 51 / 173 / 1121 ms |
| turbo en | 575 / 1120 ms | 76 / 214 / 671 ms |
| base en | 460 / 1165 ms | 118 / 224 / 1915 ms |

That is good enough for word-by-word captions and for cuts with 50 ms of padding.

**Fillers.**
- Whisper writes some fillers ("Uh,", "Um," in English with base and turbo), misspells German
  ones ("Äh" as "E.", "Ähm" as "them?" or "M"), and drops others entirely (`small` dropped "Uh").
- The alignment's empty short stretches were exactly the dropped fillers: de 8.76–8.99 s ("Ähm"
  at 8.73 s), en 7.56–7.82 s ("Um" at 7.55 s).
- So the filler detector uses three things: the lexicon, whisper's typical spellings of fillers
  as words of one or two letters ("e", "eh", "m", "hm"), and empty stretches under 0.8 s.

The silero VAD model the filter can use was not needed; the alignment does its job without a
download.

## 4. The content area

**UI Automation** (`sense.ps1 area`): the first query for a window takes 33 to 172 ms, and the
second 6 to 45 ms.
- A `Document` element was found only in Chrome.
- Opera (the user's browser), Claude's Electron app and Windows Terminal exposed none. Chromium
  builds the tree only for assistive technology.

**Win32 child windows** (`children.ps1`): every Chromium browser and Electron app draws the page in
a `Chrome_RenderWidgetHostHWND` child. Its rect is the page area.
- Opera: 65,147 2495×1233. The page area read off the take by hand was 62,141 2478×1237 (without
  the 17 px scrollbar).
- Claude's app: its main render widget, 2560,509 1920×1032.
- The enumeration takes under 5 ms.

**The picture alone** (`bands.mjs`): rows and columns at the edges that change less than 5 % as
much as the middle, over the whole take at 2 frames a second.
- The 48 s take gave [64, 148, 2492, 1232], within 4 px of the render widget.
- A take whose middle hardly changes would get no crop from this, which is the right result.

**Caret.** `GetGUIThreadInfo` gives a caret only where the app keeps a system caret; the focused
Claude app had none. A typing zoom is better placed by what the screen changes during a burst of
keys, which works in every app. The caret is used where there is one.

## 5. OCR

`sense.ps1 ocr`, Windows PowerShell 5.1, `Windows.Media.Ocr` (de-DE; Latin script, so English,
emails and keys are read too):
- the helper starts in 190 to 330 ms;
- decoding a PNG takes 5 to 100 ms;
- reading a frame takes 43 to 73 ms at its size, and 103 to 224 ms at twice its size.

What it read:
- **The landing page:** the FAQ is nearly word for word ("Can myone see…", "With LiDAR"). The
  small text on the cards is partly garbled, which is harmless.
- **The fake secrets at 1×:**
  - in small monospaced code, `0` became `O` and `l` became `I` (`DE89 … 0130 OO`,
    `AKIA10SFODNN7EXANPLE`);
  - the GitHub token line was read only as "GITHUB";
  - the 12 px grey card number was not read at all.
- **At 2×:**
  - the email, phone, IBAN (with `00`), the `sk-ant-` key, the `ghp_` token, the AWS key, the
    JWT's start, the `glpat-` token in a URL and `access_token=` were all read;
  - the card number still was not.

**What follows for the privacy guard:**
- Read frames at twice their size.
- Normalise `O→0` and `I/l/|→1` inside digit runs before IBAN and card checksums.
- Match key prefixes case-insensitively, allowing one wrong letter.
- Mask the value of any `NAME=value` line whose name contains `KEY`, `TOKEN`, `SECRET`,
  `PASSWORD` or `SESSION`, even when the value matches no pattern.
- Mask the whole value up to the end of its line.
- Never call a take safe. Tiny grey text can go unread.

## 6. Windows over the take

Dialogs, menus and notifications were not triggered: that would have shown windows on the
user's screen. The recorder's window enumeration (koffi) will classify new top-level windows over
the capture:
- `#32770` is a dialog;
- `#32768` is a menu;
- a Chromium popup (`Chrome_WidgetWin_1` with an owner) is a menu or a dialog, by size;
- `Windows.UI.Core.CoreWindow` from ShellExperienceHost is a notification.

This is checked by hand in P4-M4.

## What changes in the spec

- **Transcription:** one whisper run (queue 30 s, `max_len=1`, GPU), lines read by pattern, then
  the alignment. The model sizes are corrected to 148, 488 and 574 MB, and `small` is the default.
- **Fillers:** the lexicon, whisper's short spellings, and empty short stretches.
- **No helper while recording.**
  - `area` comes from the Win32 render widget (and Firefox's content window), through koffi.
  - The picture-only bands are the fallback.
  - The caret comes from `GetGUIThreadInfo` where there is one.
  - Typing zooms come from the screen's change during key bursts.
  - UI Automation is dropped from phase 4.
- **The helper does OCR only,** after the stop, at 2×, with the tolerant patterns above.
