# Cuttle: screen recordings that edit themselves, and videos written in code

You drive the `cuttle` command line. A project is a folder with `cuttle.json`, and a video is a
list of scenes. There are two ways to fill it, and you mix them freely:

- **Record and edit:** a take (`takes/<n>/`: the screen, optional webcam and mic, input events,
  markers), cut by `cuttle suggest`, refined in `cuttle.json`, checked in stills, rendered.
- **Write it in code:** every scene is a web page you write yourself, rendered frame by frame on
  the video's clock, with music you compose in code. No recording is needed (section 2b).

**You are free.** Cuttle renders whatever a browser can draw, so the video is not limited to the
templates or to what `suggest` makes. Write pages from nothing: a kinetic title in the product's
voice, a chart from real numbers, the product's UI rebuilt in HTML and animated, a 3D object, a
map, a diagram that assembles, a scene per feature generated by a script from data, your own
transitions, overlays and music. The templates (`motion templates`, `music templates`) are
examples to learn from and to start fast, not a menu to choose from: change a copy beyond
recognition, or ignore them. Add any page you wrote with `cuttle motion add` and check it with
`cuttle motion check`.

Before you edit `cuttle.json`, read [project.md](project.md): the format, source seconds and
source pixels, and how to find them.

## 0. Check the tools

```bash
cuttle --version
```

If the command is missing, {{INSTALL_CLI}}, and to open a new terminal. Recording and
rendering also need ffmpeg on PATH (Windows: `winget install Gyan.FFmpeg`, macOS:
`brew install ffmpeg`). Recording works on Windows and macOS. macOS asks the app that runs
`cuttle` (the terminal) for Screen Recording, Microphone and Camera, and the input log needs Input
Monitoring: a `permission-denied` error or an input warning names the setting to ask the user for.

Give the project folder as an absolute path, `-C "<project>"`, for example
`-C "$HOME/cuttle-demos/<name>"` (a `~` inside quotes is not expanded). Use `--json` for every
command except `record` (below): stdout is then one JSON document, the result or
`{ "error": { "code", "message" } }`. Exit codes: 0 ok, 1 usage or invalid project, 2 device or
permission, 3 render, 130 cancelled.

## 1. Agree the plan with the user (briefly)

- What the demo shows, and how it ends (Claude's answer, a page, a result on screen).
- Which screen: run `cuttle --json devices` and name the monitors (index, size, primary) and
  matching windows. A window (`--window`) or a region keeps the video small and private. A window
  take records that window by itself: the user may switch to other apps (and to you) meanwhile, even
  over it, and only what is done in the window is logged; closing the window ends the take. On
  Windows that needs ffmpeg 8 or newer: with an older one `record` warns and records the screen
  where the window is, so the window must stay in front.
- The format: 16:9 for X, YouTube and LinkedIn; 9:16 for Shorts, Reels and TikTok; 1:1 for feeds.
  X takes H.264 up to 1920×1200; keep demos under 60 s. A 16:9 screen fills only about a third
  of a 9:16 video: for 9:16 record a narrow window or region, or plan tight zooms.
- Webcam and mic only when asked (`--webcam`, `--mic`). `--system-audio` records what the computer
  plays (a video, an app's sounds, a game) as a track of its own beside the mic: use it when the
  demo has sound; it goes down under the voice by itself (`look.audio.system`, `systemVolume`,
  `systemDuck`). A muted mic is reported as a warning;
  after the mic's first second the output says whether it hears sound (`mic: it hears sound`, or
  `it hears almost nothing`: then ask the user to check the mic before going on).
  When the user will speak, Cuttle transcribes the mic on this computer and cuts filler words and
  pauses. That needs a speech model: `cuttle --json models` lists them. If none is downloaded, ask
  the user before `cuttle models download small` (488 MB, once). Tell them that a slip needs no
  new take: press Ctrl+Shift+Alt+X (or say "nochmal", "again", or just pause and begin the
  sentence again) and do the bit again.
- Ask the user to make text large (terminal font 16 px or more, or zoom the browser), to close
  private windows, to switch on Do not disturb (Cuttle masks the notifications it sees, but none is
  better), and to use a clean folder or browser profile.
- Whether it needs a recording at all: a promo, a launch reel, an explainer or a social clip can be
  written entirely in code (section 2b), or mix pages with a short take.
- The project folder: a new one per demo (`record` creates it).
- A demo with steps (open this, then that) gets a script: write the steps into `cuttle.json`
  before the take (`script`, see [project.md](project.md); `cuttle init "<project>"` makes the
  folder first). The take starts at the first step, Ctrl+Shift+Alt+N moves to the next one
  (Ctrl+Shift+Alt+B back), and each step becomes a `step` marker. The prompter that shows the
  steps during the take is the app's: when the user records from the app ("Record again"), it
  sits by the recording bar. For `cuttle record`, list the steps for the user before the take.

## 2. Record

Never start Claude Code yourself, and never change Claude's settings to trust a folder. For an
agent demo, ask the user to start Claude Code in the demo folder in their own terminal and to
accept the trust dialog. Suggest `claude --setting-sources "project,local" --strict-mcp-config`,
which keeps their global hooks and plugins out of the video (in PowerShell keep the quotes: it
reads `a,b` as an array).

`cuttle record` runs until a stop trigger. Start it **in the background** (Bash
`run_in_background`) **before** the user acts, and without `--json`, so its status lines show.
Always give it a stop file and a time limit:

```bash
cuttle -C "<project>" record --monitor 0 --until-file "<project>/stop" --until-claude "<demo folder>" --max 600
```

- `--until-file "<project>/stop"`: the take ends when the file appears. **This is how you stop
  it**: create the file (`touch "<project>/stop"`) when the user is done or something goes wrong,
  but only while the task still runs (a file left after another trigger ended the take blocks the
  next one). Never stop the background task by killing it: a killed take is cut off, and
  `cuttle.json` still points at the previous take. After a stop by file, `record` removes the file
  again.
- `--until-claude "<folder>"`: also ends the take 2 s after the first Claude Code session in that
  folder that prompts after the start finishes its turn; its prompt, tool calls and answers become
  markers. A turn that leaves commands, agents or monitors running in the background does not end
  it: the take ends after Claude's answer once they are done (their results are in it), or 60 s
  after the last step in that session when one never ends (a server it started; the output then
  says so). If that folder is the one you run in, tell the user not to write to you until the
  recording has stopped: your own next turn would end it.
- `--until-idle 5`: also ends once the screen and the input have rested 5 s.
- `--max <seconds>` is the safety net (it counts recorded time, not pauses). The user can also stop
  with Ctrl+Shift+Alt+S, add a marker with Ctrl+Shift+Alt+M and pause or resume with
  Ctrl+Shift+Alt+P (Alt is Option on a Mac; nothing is recorded while paused; the pieces are
  joined at the stop). With a script, Ctrl+Shift+Alt+N goes to the next step and
  Ctrl+Shift+Alt+B back, and the output shows each step (`step 2/5: Open the settings`). Other
  sources: `--window "<part of the title>"`, `--region x,y,w,h` (pixels of `--monitor`).
  `--countdown 3` is the default.
- A project open in the Cuttle app is refused (`project-open`): the app records it itself
  ("Record again"). Ask the user to record there or to close it; `--force` only if they say so.

The Bash tool's result names the background task's output file. Wait until the recording runs
(at most 40 s: the countdown plus up to 20 s for the tracks to start):

```bash
for i in $(seq 40); do grep -qE "recording takes/|^error:" "<output file>" && break; sleep 1; done; cat "<output file>"
```

If it shows `recording takes/<n>`, tell the user to start (for an agent demo: to send the prompt
in their Claude Code session). If it shows `error:`, or nothing after 40 s, the recording did not
start: read the error. Do not rely on the user's "done" for timing: `suggest`
trims the quiet start and end anyway. When the take ends, the output shows
`recorded takes/<n>: 42.0 s …` and `cuttle.json` uses the take as one clip over the whole take. If
the task ended without that line (killed, crashed), run
`cuttle -C "<project>" --json recover takes/<n>` before anything else. A new take replaces the
previous take's scenes and overlays; older versions stay as `cuttle.json.bak`, `.bak.1` and so on.

**A video made elsewhere** (a phone, OBS, a recording the user was sent) becomes the take with
`import` instead of `record`; `--from` and `--to` (seconds of the file) take a stretch of it:

```bash
cuttle -C "<project>" --json import "<file>" --from 12 --to 40
```

The picture is converted as a recording is (30 fps, BT.709, at most 3840 px on its long side) and
the sound becomes the mic. An imported take has no input events and no markers: `suggest` cuts it
by its picture and sound alone, so add zooms by hand where something happens.

## 2b. A video written in code (no recording)

For a promo, a launch or feature video, an explainer, an animated title or a social clip, write the
video as pages. Read [motion.md](motion.md) and [music.md](music.md) first.

1. `cuttle init "<project>"`, and set the format (`output` in project.md) and the brand (`theme`,
   or `cuttle -C "<project>" --json brand apply "<name>"`).
2. Plan it like a motion designer: a storyboard of scenes with their seconds (a 20–40 s video is 6–10
   scenes of 2–5 s), the one idea of each, how one hands over to the next, and the beats the music
   lands on. Show the user the storyboard before you build.
3. Give the video one design: `motion/shared.css` and `motion/shared.js` (palette, type scale,
   easing, shapes, the background, the logo) that every page imports, so the scenes look like one
   film, not a set of templates.
4. Write each scene as `motion/<name>/index.html`: from nothing, or from a template's page you take
   apart. Pages can read data and images of the project (`./data.json`, `/stills/home.png` from
   `capture-page`), and a script you write may generate many pages from data (one per feature, per
   number, per customer quote).
5. Add each in order: `cuttle -C "<project>" --json motion add motion/<name>/index.html --duration 3`
   (`--first`, `--after <scene>` to place it, `--label` for the timeline;
   `--as transition --into <scene>` for a transition page of your own). Check it:
   `cuttle -C "<project>" --json motion check motion/<name>/index.html`, read the sheet, fix every
   error, check again. While you write many pages, `cuttle -C "<project>" --json watch` (run in the
   background) does the checking: each save reruns that page's check, the music page's or the
   preview, and prints a line of JSON (`check`, `src`, `changed`, `errors` first, `result.sheet`).
6. Write the music for these scenes (music.md): from a template you make your own, or a page from
   nothing that you make the music with `cuttle -C "<project>" --json music set --src music/<name>/index.html`.
   Hit the scene changes.
7. `cuttle -C "<project>" --json preview` for the whole video, then render (section 4). Render each
   format the user wants: pages size themselves from the short side, so one set serves 16:9, 1:1
   and 9:16 (check each with `preview --format`).

A recorded take can join later: `cuttle record` adds clips to the same project, and your pages stay.

**A narration** finishes a video written in code, or a take the user did not want to speak over.
Write it with the user (what each scene says, in their language and tone), then:
`cuttle -C "<project>" --json voice use de_DE-thorsten-medium` (`voice list` shows the voices on
this computer, a woman's and a man's in English, German, French and Spanish; ask before
`voice download <name>`, 21 MB once), or `voice use <voice ID> --elevenlabs` when the user has an
ElevenLabs account (`ELEVENLABS_API_KEY`; `voice list --elevenlabs` lists their voices). Add a
line per scene: `cuttle -C "<project>" --json voice add "<text>" --scene <id> --at 0.3`, or
`--file <recording>` for a voice made elsewhere (Higgsfield, another TTS, a studio take). Then
`voice render`: it says each line's length and where it plays; a line longer than its scene runs
into the next (it says so): shorten the text or lengthen the scene. The music ducks under it.

## 3. Edit

```bash
cuttle -C "<project>" --json suggest
cuttle -C "<project>" --json preview
```

`suggest` trims the quiet start and end, cuts idle stretches, speeds up waiting (Claude at work),
and crops each clip to the content: a browser's page without its tabs and bars, without the
taskbar (from the window's content area the recorder saw, else from the screen's still edges;
`--no-crop` leaves it out). It zooms on Claude's answer, on a dialog while it is open ("Dialog";
`--no-dialog-zooms`), in where someone types, following the text along ("Typing": the camera
moves on as the text leaves the middle of the view; `--no-typing-zooms`), and where clicks
happen at normal speed ("Click", "Clicks"; `--no-click-zooms`; `--no-zoom` leaves out every zoom).
With a script, it titles each step where the video shows it (a text, or the step's `motion`
template; `--no-step-titles`) and zooms on where each step happens ("Step 2"; `--no-step-zooms`),
before the clicks' zooms. Its `notes` say what it did, in
source seconds. It replaces every clip and the zooms it made before (tagged `auto`; masks, texts,
cuts, stills, cards and zooms made by hand stay), so run it once, before your hand edits. Its clips and zooms have ids, and labels where Claude's markers say
what they show ("Claude at work", "Answer"): keep them when you edit, and give items you add an
unused id and a label (project.md).
To change many items at once, pick them and act in one write:
`cuttle -C "<project>" --json items --made click --between 30,60 --off` turns off the click zooms of
that stretch (`--kind zoom,mask`, `--auto`, `--yours`, `--ids z3,m1` pick too; `--on`, `--delete`,
`--shift -0.5` in source seconds). Without an action it lists what the filters pick.
For a take recorded without `--until-claude`, add `--claude "<demo folder>"` to read the markers
from Claude Code's transcript.

**Speech.** With a mic, `suggest` keeps the stretches where someone speaks (never cut or sped up),
and when a speech model is downloaded it first transcribes the mic into `takes/<n>/transcript.json`
(every word with its source seconds; read it to find what was said where). It then cuts filler
words ("äh", "um") and pauses longer than a second down to 0.4 s, only where the picture rests
(cuts tagged `filler` and `pause`). `--no-speech` leaves the speech out.
`cuttle -C "<project>" --json transcribe --language de` transcribes again (`--model` picks one).
Transcribing also writes a cleaned-up mic (less noise, even loudness) that the video plays.

**Slips.** The mistake key (Ctrl+Shift+Alt+X, or the scissors in the recording bar) marks a slip
in `markers.json` (kind `retake`). A spoken cue counts too when the bit is then said again ("…die
Art. Nochmal. Die App erkennt die Art …"; also "noch mal", "again", "one more time"), and so
does a sentence begun again after a pause ("Dann klickt ihr auf … Dann klickt ihr auf
Exportieren"). `suggest` cuts each slip from the pause before it to where the bit starts again
(cuts tagged `retake`, "Retake", "Retake: “Nochmal”" or "Restart: “Dann klickt ihr auf”"); the
key needs no speech model. Every speech cut begins and ends where the mic is quiet: its notes say
how many edges it moved there, and which cuts it left out because the words ran together. Check
each with `preview --at` just before and after the cut; if it took too much or too little, move
its `from` or `to` and remove its `auto`.

**Subtitles.** A transcribed take gets subtitles in the video (`captions`, project.md): as
subtitles at the bottom, `karaoke` (the spoken word in colour) or `bold` (a few big words, for
9:16). `cuttle -C "<project>" transcript --text` prints what was said; `--srt` the subtitles on
the video's time. Read them for misheard names and fix them in `captions.fixes`. Check a still
with a subtitle on it before you render.

`preview` writes 12 stills and `preview/sheet.png`. **Look at the sheet** (Read the PNG). Each
still in the JSON has its output second `t` and the `source` second it shows. For details, run
`cuttle -C "<project>" --json preview --at 3.5 --at 12` (output seconds). Each run replaces the
stills in `preview/`; add `-o "<folder>"` to keep a set.

Then refine `cuttle.json` ([project.md](project.md)) and preview again:

- **Privacy first.** `suggest` masks each notification (a toast, the notification centre) while it
  was open (`auto: "notification"`). It also reads the screen's text (Windows' own OCR or macOS's
  Vision, on this computer) and masks what it finds: email addresses, keys and tokens, the value of a `…KEY=`,
  `…TOKEN=` or `password:` line, IBANs, card and phone numbers, and random-looking strings (a key
  without a known prefix; masks tagged `auto: "privacy"`, following text that scrolls frame by frame). The text it
  keeps (`takes/<n>/screen-text.jsonl`) has each find replaced by a mark such as `⟦key-qwhzbtrk⟧`. Pass the user's name and address once with
  `--mask "<word>"` (kept in cuttle.json). This is a help, not a guarantee: the OCR misses small
  grey text and some lines, so **still look** yourself. Look for names, email addresses, tokens and
  API keys, file paths with user names, hook or plugin errors, and notifications.
  - Twelve stills miss things: step through sped-up stretches with `preview --at` about every
    output second.
  - For each find, take the still's `source` second and run
    `cuttle -C "<project>" --json frame <source second> --grid`. Read that PNG: a numbered grid
    every 100 source pixels. Read the rect off it, generously.
  - Find when it appears and when it goes: run `frame` at earlier and later source seconds
    (halving the step), then pad 0.5 s on each side for the mask's `from` and `to`. Text that
    scrolls moves: give each position its own mask, or cut the stretch out.
  - Use `fill` for secrets. Check every mask with
    `cuttle -C "<project>" --json preview --masks`: stills 0.1 s before each mask starts, inside its
    start and its end, and 0.1 s after it ends, a row of `preview/sheet.png` per mask (`masks` in
    the JSON says which still shows which mask's edge). Inside, what it hides must be covered;
    before and after, it must not show yet (or no more). Where it does, move the mask's `from` or
    `to` out by 0.5 s and check again. For a mask's middle, use `preview --at` (output second =
    scene start + (source second − `from`) ÷ `speed`).
  - Masks apply to clips only: look at a captured page yourself before you add it.
  - Only rendered videos and stills are masked. The project folder keeps the take as recorded
    (`takes/`, `.cuttle/`): never upload, attach or commit the folder, only the rendered video.
- **Story.** Trim what does not help. Keep the prompt readable (1.5 s or more) and the answer on
  screen for 2–3 s. A speed-up shows a "12× speed" badge.
- **Length.** For a length the user names (X: under 60 s), fit it last, after your zooms and
  texts: `cuttle -C "<project>" --json fit 45`. It cuts where the video rests (`auto: "length"`),
  never speech, clicks, typing, a zoom or a text, and says the shortest it can make when the
  length is out of reach. A new fit replaces the last; `fit --off` takes it out.
  (`suggest --length 45` fits in the same run, before any hand edits.)
- **Focus.** Add or fix `zooms` on what matters: 2–4 s on the answer or a result, with the rect
  read off a `frame --grid`. Over a sped-up clip, durations are source seconds: 3 s at 12× is a
  quarter second on screen (see project.md). A zoom can follow what moves: give it a path with
  `cuttle -C "<project>" --json zoom-path z3 --at 14.2 --rect 900,300,640,400` (a move at 14.2 s;
  `--ease smooth`, `linear` or `jump`), checked with `frame` at and after the move. Point at what
  the viewer must not miss:
  `cuttle -C "<project>" --json annotate arrow --at 12.5 --from 300,700 --to 620,410 --text "Click here"`,
  or `box`, `highlight`, `spotlight`, `magnifier` with `--rect x,y,w,h` (off the same grid); one or
  two per step, never on a sped-up clip. With a webcam take, open and close with the face:
  `cuttle -C "<project>" --json camera full --at 0 --duration 4` (the camera over the whole video),
  `side` (beside the screen while someone explains) or `large`.
- **Look.** When `cuttle --json brand list` shows brand kits, ask which one the video wears and run
  `cuttle -C "<project>" --json brand apply "<name>"`: the brand (name, URL, logo, colours, heading
  font) for the motion pages, the background, frame and cursor. Without one, set `theme` (project.md)
  and offer to keep it with `brand save`. Set `look.frame.title` (e.g. `claude · ~/demo`) and a
  background: `cuttle -C "<project>" --json background gradient --from take` takes the product's own
  colours, `background --wallpaper` puts the desktop's wallpaper behind the window, softened;
  `flow`, `bokeh` and `dots` move quietly. The frame fits what was recorded: `windows-dark`, `terminal`,
  `browser-dark`, or `iphone` and `android` around a phone-shaped take or page; `look.watermark` puts the
  brand's logo in a corner. Add a `texts` caption where a step is not obvious, coming in with
  `"enter": "pop"`, `"slide"`, `"typewriter"` or `"words"` where it should draw the eye (project.md). Typing clicks softly, a click per key where the clip
  is heard (`look.audio.typing`, `typingVolume`); switch it off when the user wants a quiet video.
  The shortcuts pressed show as keycaps (`⌘ ⇧ P`, `Ctrl Z ×3`; `look.keys`): `show: "keys"` adds
  Esc, Enter and the arrows for a keyboard-driven tutorial, `enabled: false` hides them.
- **Pages.** `cuttle -C "<project>" --json capture-page <url or file> --scroll --add` appends a
  scrolling still of a web page (the result the agent built); add `--wait 2500` for slow maps or
  fonts. It goes after every scene, so capture pages before you add the end card (or move the
  still in `scenes`).
- **Motion.** Anything a browser draws can be in the video, and you are free in what you make: a
  kinetic intro, an end card with the product's look, a chart that builds, a 3D shot, a callout on
  every click, a lower third over the clip, the product's UI rebuilt and animated. Read
  [motion.md](motion.md) first. Write the page yourself into `motion/<name>/index.html` and add it:
  `cuttle -C "<project>" --json motion add motion/<name>/index.html --first` (a scene;
  `--as overlay --at <source s>` over the clips). A template is a quicker start
  (`cuttle -C "<project>" --json motion new title --first`; `motion templates` lists them): make the
  copy this video's own. Check every page before you preview the video:
  `cuttle -C "<project>" --json motion check motion/<name>/index.html` renders it frame by frame
  into `preview/motion-<name>/` (`--duration`, `--at`) and lists its `errors` and `console`.
  Read the sheet, fix every error, then look at it in the video with `preview --at`.
- **Music.** Give the video music written for it: read [music.md](music.md). Write the page yourself
  (`cuttle -C "<project>" --json music set --src music/<name>/index.html` makes it the music), or
  start from a template (`cuttle -C "<project>" --json music new pulse`; `music templates` lists the
  moods) and make it this video's own (tempo, key, chords, instruments, how it builds over the
  scenes, hits on the cuts). Never ship a template unchanged: no two videos should sound alike. Check it with
  `cuttle -C "<project>" --json music check`: it renders the music alone into `preview/music.wav`
  and `preview/music.png` and reports each part's level, the hits on the scene changes, the
  loudness and the page's errors. Read the sheet, fix the errors, check again. It goes down under
  speech by itself; `music set --volume`, `--duck` and `--param` tune it, and `--stem drums=0.5`
  sets a stem's level ("less drums", "no lead under the voice"). Ask the user before
  adding music to a video with a voice that should stand alone.
- **Sounds.** A sound at a moment, without the music: `cuttle -C "<project>" --json sound add whoosh --at 12.4`
  (source seconds) or `--scene s5 --at 0.2`; `sound list` has the built-in sounds. A motion page
  asks for its own with `cuttle.sound(…)` (motion.md); the templates come with theirs.
- **Transitions.** A page in place of the crossfade into a scene: your own,
  `cuttle -C "<project>" --json motion add motion/<name>/index.html --as transition --into <scene id>`, or the
  fold, `cuttle -C "<project>" --json motion new fold --into <scene id>` (motion.md). One or two a
  video, where something changes.
- **End card.** A `card` scene at the end with the product name and URL, or a `motion` scene.

## 4. Render

```bash
cuttle -C "<project>" --json render --format 16:9
```

With a transcript, `--srt` and `--vtt` also write the subtitles next to the video, and
`--no-captions` leaves them out of the picture. Where the video goes sets its loudness:
`--loudness youtube` (-14 LUFS: YouTube, Spotify, TikTok, Instagram), `podcast` (-16) or `broadcast`
(-23) brings the whole mix there with its peaks under -1 dBTP (`look.audio.loudness` keeps it in the
project); the JSON's `loudness` says what the video measures. Use `youtube` for a video for the web. Run it in the background when the video is longer than about a minute; the Bash tool stops long
commands. It writes `out/16x9.mp4` (or `-o <file>`); the JSON has the frames, the seconds and the
encoder (`stats`). For 9:16, check `preview --format 9:16` first. Render every format the user
wants in one run, `render --format 16:9 --format 9:16 --format 1:1` (each to `out/<format>.mp4`,
the JSON's `videos`): the sound is made once for all of them, faster than one render each.
`render --all <folder>` renders every project in a folder (`projects` in the JSON). Tell the user the file's path and length. Do not upload it anywhere.

With a script, the video file has the steps as its chapters (`chapters` in the JSON, output
seconds). `cuttle -C "<project>" --json chapters` gives them as lines for a YouTube description
(`youtube`) and says why YouTube would not show them (`problems`: fewer than three, or one shorter
than 10 s). Give the user the lines when the video goes to YouTube.

## When something fails

- `device-not-found`: run `cuttle --json devices`. Names must match exactly (`--mic "<name>"`).
- `invalid-project`: the message names the field, counted from 0 (`scenes[1].to: …`); fix
  `cuttle.json`, or go back to `cuttle.json.bak`. A clip must end inside the take.
- `record` refuses a stop file that already exists: delete it (`rm "<project>/stop"`), then start
  again.
- A crash or a killed recording: `cuttle -C "<project>" --json recover takes/<n>` makes the take
  usable.
- `suggest` found no Claude markers: pass `--claude "<demo folder>"`.
- `model-missing` (or the note "the mic was not transcribed"): no speech model is downloaded; ask
  the user before `cuttle models download small`.
- `voice-missing`: the narration's voice is not on this computer; ask the user before
  `cuttle voice download <name>` (21 MB). `voice-key`: ElevenLabs has no key, or refused it: ask
  the user for theirs (`ELEVENLABS_API_KEY`), never write it into a file. `voice`: the voice failed
  on a line (ElevenLabs' message says why: a voice ID that does not exist, credits).
- `ffmpeg-old`: nothing here can transcribe: ffmpeg has no whisper filter (before 8.0, or built
  without whisper, as every macOS ffmpeg is) and whisper.cpp's `whisper-cli` is not installed. Ask
  the user to run `winget upgrade Gyan.FFmpeg` (macOS: `brew install whisper-cpp`).
- `frame` says no frame starts at that second: the take ends there; take an earlier second.
- A render fails with `render`: try `--encoder software`.
- `conflict`: `cuttle.json` was saved by someone else (the user, or the Cuttle app) while the
  command ran, and nothing was written. Read the file again, then run the command again.
